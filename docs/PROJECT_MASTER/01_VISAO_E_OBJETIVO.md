# 01 — Visão e Objetivo

## Produto final desejado

O Vale o Clique deve ser um **gerador automático de criativos de produto**, não um gerador de slides. A entrada ideal é um link de produto — inicialmente Shopee — e a saída é um pacote criativo pronto para revisão/publicação:

- assets recuperados automaticamente;
- fatos e seller claims separados;
- estratégia criativa específica para o produto;
- storyboard visual;
- narração;
- trilha/SFX;
- vídeo vertical final;
- relatório de auditoria criativa e técnica.

## Experiência esperada

O sistema deve ser capaz de receber um novo produto sem exigir que o usuário envie manualmente cada JPG, escreva cada cena ou monte o vídeo no CapCut.

Fluxo ideal:

`link do produto -> pesquisa -> assets -> estratégia -> storyboard -> gate visual -> áudio -> render -> gate final -> MP4`

## O que significa "automático"

Automático não significa repetir um template. Significa tomar decisões diferentes de acordo com o produto:

- escolher o tipo de hook;
- decidir quando revelar o produto;
- decidir quais claims merecem prova visual;
- escolher quais assets usar ou buscar;
- variar composição, ritmo, tipografia e densidade de informação;
- saber quando usar silêncio, SFX ou narração;
- rejeitar um criativo fraco antes do render final.

## O que significa "individual"

Um teclado não deve receber o mesmo anúncio de um aspirador, uma luminária ou um item de cozinha. A estrutura criativa deve nascer das propriedades do produto, do contexto de uso, dos assets disponíveis e dos padrões aprendidos.

## Princípios não negociáveis

### 1. Primeiro segundo vende continuação
O hook existe para impedir o scroll, não para apresentar uma ficha técnica.

### 2. Produto é protagonista
Texto complementa a imagem. Texto gigante cobrindo o produto é sinal de falha de direção.

### 3. Cada mudança visual precisa trazer informação nova
Trocar apenas a frase mantendo o mesmo frame é slideshow, não edição.

### 4. Fato não pode ser inventado
Seller claims permanecem atribuídos. Imagem gerada por IA nunca pode servir como prova de especificação do produto.

### 5. Contexto pode ser gerado; prova deve ser real
Cenas de problema, desejo ou ambientação podem ser sintéticas. Close de característica, produto, embalagem, preço e especificações precisam de fonte rastreável.

### 6. Storyboard vem antes do MP4
Se os frames principais já parecem ruins, renderizar o vídeo inteiro só desperdiça tempo.

### 7. Benchmark precisa ser comprovável
Referência textual não conta como vídeo analisado. O sistema só pode declarar que "viu/analisou" mídia que realmente processou.

### 8. Human watchability supera validade técnica
H.264/AAC/30 FPS são requisitos básicos. Eles não tornam um anúncio bom.

## Meta qualitativa

Ao pausar o vídeo em qualquer frame importante, o resultado deve parecer uma peça intencional de anúncio/social content — não uma imagem de catálogo encaixada automaticamente com texto por cima.
